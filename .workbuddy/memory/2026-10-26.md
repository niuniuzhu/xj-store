- 说明：CSS 限制——`background-image`（渐变）本身无法过渡，故仅能靠底层背景色平滑 + 渐变半透明化来弱化跳变。主按钮渐变（`#79b0ff` 硬编码）暂未改，避免改动既有外观；如后续要彻底消除按钮跳变，可改为纯 `background: var(--primary)` 或两端用主题变量。

## 重大修复：签名算法 bug（"签名计算失败"真因，与密钥无关）
- 用户报「密钥很复杂导致签名计算失败，检查密钥是否错误」。实测结论：**密钥没错，是签名串把每个值做了 URL 编码（phpUrlencode），而标准易支付要求用【原始值】拼接**。只要参数含中文（商品名）/空格（sitename "XJ Store"）就会对不上 → 网关判「签名计算失败」。
- 验证方法（已固定为可复用流程）：直接把三种编码的签名请求打到真实网关 `https://dash.bxyvps.cn/submit.php`（须带 `User-Agent`+`Referer` 否则 500），看返回。
  - phpUrlencode / rawurlencode 算法 → 网关明确「签名计算失败」；
  - **RAW 原始值算法 → 网关过验签**（alipay/wxpay 早期低频率实测 302 放行，证明算法对）；`type=usdt` 即便签名正确也返回「系统发生错误」（商户 348884 网关侧无可用 usdt 通道，与签名无关）。
- 修复：`server/pay-server.js` 的 `signString()` 改为标准易支付原始值拼接（去掉 `phpUrlencode` 函数，顺带满足用户"不要太复杂"）；`makeSign`/`verifySign` 共用该函数，自动一致。
- 端到端校验：取服务端 `/api/pay` 实际返回的 payParams，本地按标准 RAW 算法复算 MD5，与返回 sign **完全一致（MATCH:true）** → 签名彻底正确。
- **注意**：网关对重复 `out_trade_no` 或高频请求会返「系统发生错误」(500 ThinkPHP)，与签名无关；实测时每个号只用一次、低频打，避免把商户 IP 打进黑名单。
- 遗留待用户决策：`type=usdt` 在网关侧创建订单失败（系统发生错误）。若要让支付真正完成，需 (a) 用户在商户后台开通 usdt 通道/确认正确通道码，或 (b) 把网关 `type` 改为实际所选通道（alipay/wxpay，已验证可放行）。当前代码仍按用户要求发 `usdt`（config `payType:"usdt"`）。
