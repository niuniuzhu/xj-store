### 切换为 RSA 签名
- **关键认知**：RSA 签名必须用**私钥**；用户提供的那串是 2048 位 RSA **公钥**（PKCS#8），只能用于验签。
- 密钥文件放 `server/keys/`：
  - `gateway_public.pem` —— 用户提供的平台公钥，用于**回调验签**
  - `merchant_private.pem` —— 本地生成的商户私钥，用于**下单签名**
  - `merchant_public.pem` —— 商户公钥，**需用户自行上传到 dash.bxyvps.cn 后台**（否则平台验签失败）
- `server/config.json`：`signType: "RSA"`、`rsaAlgo: "RSA-SHA256"`（若平台要求 SHA1withRSA 则改为 `RSA-SHA1`），MD5 密钥保留作为回退。
- 服务端改造：`signString()` 抽公共待签串；`makeSign()` RSA 用私钥 / MD5 用密钥；`verifySign()` RSA 用平台公钥 / MD5 比对。
- 验证结果：sign_type=RSA、签名 344 字符 base64、商户公钥验签通过；错配密钥与篡改金额均返回 fail。
- 已创建 `.gitignore` 忽略 `server/keys/`、`server/config.json`、`server/data/`，防止密钥入库。
- **网关实测限制**：`sign` 字段最大 32 位 → 该商户当前只接受 MD5；RSA(344 位) 被拒。config.json 已回退 `signType: "MD5"`，RSA 密钥保留待后台开通后再切。

## 重要排障经验（可复用）
- **body 用 flex 列布局时，带 `margin: 0 auto` 的子项会被取消拉伸**，退化成 max-content 宽度（表现为"页面莫名变窄"，本项目实测恒为 865px）。修法：给容器补 `width: 100%`。本项目 `.layout` / `.wrap` / `.header-inner` 均需补。
- 可用 Chrome headless 精确量布局：`chrome.exe --headless=new --user-data-dir=<Windows风格路径> --dump-dom <探针URL>`，探针页用 iframe 加载目标页并把 `getBoundingClientRect()` 写进 DOM。注意 user-data-dir 必须给 Windows 路径，否则会挂到已运行的浏览器实例上导致无输出。
  - 签名规则按易支付(epay)通用协议：剔除 sign/sign_type 与空值 → 参数名 ASCII 升序 → `k=v` 用 PHP 风格 urlencode 拼接 → 末尾拼密钥 → MD5 小写。
  - `server/config.json` 的 `mock:true` 可切本地演练模式（不请求真实网关）。
- 网关：`https://dash.bxyvps.cn`，商户号 348884，实测 `/submit.php`、`/mapi.php`、`/api.php` 均返回 200（符合 epay 特征，但签名规则需用户对照官方文档确认）。
- checkout.html 支付方式改为 **支付宝 / 微信** 两项；提交流程：本地存订单 → POST /api/order → GET /api/pay → 跳转网关；失败降级为待支付订单。
- order.html 新增 `syncFromServer()`，打开时从服务端同步订单状态（回调后置为已完成）。
