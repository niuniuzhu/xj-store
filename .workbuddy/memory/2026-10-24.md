## 修复：商店与账号中心登出不联动（单点登出）
- 现象：在会员中心/某页点退出登录（清 `xj_user`），已打开的账号中心标签页仍显示登录态。
- 根因：`xj_user` 是前台所有页共用的登录态，但 base.js 没有监听 `storage` 事件，跨标签页不会同步。
- 修复：`assets/base.js` 的 `user()` 之后新增全局 `window.addEventListener('storage', ...)`，当 `e.key === 'xj_user'` 时 `location.reload()`。
  - 各页自身登出（me/account-center/account-server）已 `removeItem('xj_user')` + 本页 reload，不受 storage 自触发影响（同源自己改不触发自己）。
  - 联动效果：任一页登出 → 其它已打开标签页自动刷新 → 同步为未登录/门禁。顺带也实现了单点登录联动（其它页登录也会刷新同步）。
- 静态文件改动，无需重启 Node；浏览器刷新即生效（已有 `Cache-Control: no-cache`）。
- 注：store.html 本身无独立退出按钮，会员登录后顶栏用户名 pill 链接到 me.html，退出在会员中心内。

- **关键优先级知识点**：代码是 `CFG.key = process.env.XJ_PAY_KEY || cfgRaw.key`，即 **`.env` 优先于 `config.json`**。改密钥必须改 `.env`（或同时改两处），只改 `config.json` 无效。
- 已按用户选择把 `.env` 与 `config.json` 双改�� `9ZUQ...`，并用「用服务端真实 payUrl 参数独立复算签名」验证一致（`9ZUQ` 匹配、`T38WP` 不匹配）。
- 网关实测要点（供以后排查）：
  - `https://dash.bxyvps.cn/`、`/submit.php`、`/api.php` 均返回 200，网关是标准易支付结构。
  - **裸 curl 请求会拿到 HTTP 500「系统发生错误」**；加上浏览器 `User-Agent` + `Referer` 后才返回正常业务页（"发起支付失败 / 签名计算失败"）。这是网关对请求头的要求，**不是 key 错误**——两个 key 的表现完全一致，无法据此区分 key 真伪。
  - 因此 **key 正确性只能靠服务端签名与本地独立复算比对**（用 payUrl 里的真实参数重算 md5(str+key)），不要靠网关报错文案判断。
